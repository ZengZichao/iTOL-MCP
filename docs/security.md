# iTOL-MCP 安全设计

## API 密钥安全

| 措施 | 实现 |
|------|------|
| 存储位置 | `~/.config/itol-mcp/.itolapi.key`（默认），拒绝写入工作区 |
| 文件权限 | 写入时 `chmod 600`；读取时检测 group/other 权限位，存在则 WARNING，`strict_permissions` 下直接拒绝 |
| 内容规范 | 单行 UTF-8，去首尾空白；长度 8–128；含换行/控制字符拒绝 |
| 解析优先级 | 工具参数 `api_key` > 环境变量 `ITOL_API_KEY` > 密钥文件 |
| 脱敏 | 任何返回、日志、异常、资源内容中以 `***REDACTED***` 替代；日志过滤器对已知来源正则脱敏 |
| 生命周期 | `itol_config_set_api_key` 仅本次调用内存中持有；提示泄露即轮换 |
| 越权防护 | 密钥仅用于与 `itol.embl.de` 的 HTTPS 请求，绝不随其他域名发送 |

## 路径安全

- **工作区白名单**：所有文件读写经 `Workspace.resolve()`，结果为绝对路径且必须
  `is_relative_to(workspace_root)`；`~` 展开后解析 `symlink`（realpath 后校验），杜绝符号链接逃逸；
- **输出文件名**：拒绝 `/`、`..`、空名、隐藏文件、非法字符；外部值（如 `tree_id`）经
  白名单正则（`[A-Za-z0-9_\-]+`）消毒后才用于文件名；
- **临时文件**：系统 temp 目录 + 权限 600 + `try/finally` 清理（ZIP 打包等）；
- **禁止写入**：工作区内的 `.itolapi.key`、`<工作区>/.git` 等敏感路径一律拒绝。

## 网络安全

- 仅 HTTPS（iTOL 三个端点 hard-code `https://`）；
- 统一超时：上传/导出 120s，健康探测 5s；
- 重试策略：`429/500/502/503/504` 最多 3 次、指数退避；**重试 POST 上传前记 WARNING**
  （iTOL 无幂等键，可能重复建树），指引用户核对项目；
- 导出响应校验：`text/html` 错误页识别、短文本错误识别、按格式最小体积识别，
  防止把错误页当成果物落盘；
- 上传/导出频率约束：工具描述内置「两次调用间隔数秒」提示；`wait` 参数支持主动等待。

## 输入安全

| 输入 | 防护 |
|------|------|
| 树文本 | 控制字符/双向 Unicode 检测（ERROR）；括号平衡、负分支长度、重复 tip 名、多根校验 |
| 表格 | 列数一致性校验；超大文件（>50MB）拒绝；行数上限（默认 200,000 行） |
| 模板参数 | `parameters` 键名按类型白名单校验（未知键 WARNING 忽略）；行内字段数校验 |
| 颜色 | `#RRGGBB`/`#RRGGBBAA`/命名色白名单，拒绝非法输入 |
| ZIP | 仅由服务端自身生成（不接受外部 ZIP 解压），无 zip 炸弹面 |
| 长度 | 内联文本参数上限 5MB（pydantic 校验） |

## 日志与隐私

- 日志轮转：`logs/itol-mcp.log`，10MB×3；
- ISO8601 时间戳、级别、模块、消息；
- 日志级别：`INFO` 记录调用摘要（工具名、耗时、结果 success），`DEBUG` 记录参数
  （**密钥已脱敏**）；树/模板内容默认不落入日志，仅记录路径与行数；
- 不采集任何遥测；不做外联遥测上报。

## 运行权限建议

- 以最小权限用户运行；如在 HPC/共享机器上使用，务必限定 `workspace_dir` 为私有目录、
  密钥文件 600；
- streamable-http 模式默认绑定 `127.0.0.1`，不暴露公网；如远程访问需自行接入反向代理
  与鉴权（服务端不内置公网监听）。

## 密钥泄漏应急

1. 立即在 iTOL 账户页（https://itol.embl.de/userInfo.cgi）轮换 API Key；
2. 用 `itol_config_set_api_key` 写入新密钥；
3. 检查 iTOL 项目内是否出现非预期上传；
4. 对已泄露的旧密钥不再归档（日志已脱敏，无需清理）。
